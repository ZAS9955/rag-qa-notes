# 主流工具与模型选型

开发框架方面，LangChain 是生态最大、组件最全的，适合快速搭原型，但抽象层多、排查问题时容易被封装绕晕；LlamaIndex 专注 RAG 场景，索引和检索的默认配置更合理，文档型应用上手更快。学习阶段建议用框架理解流程，但最好也用原生代码手写一遍最小 RAG，明白框架背后做了什么。

向量数据库方面，FAISS 是 Meta 开源的库，单机跑得快，适合实验和小规模；Chroma 轻量易用，自带持久化，适合原型；Milvus 和 Qdrant 面向生产，支持分布式和大规模数据；pgvector 则是给 PostgreSQL 加向量能力，如果团队已有 PG 数据库，运维成本最低。选型的核心考量是数据规模、是否需要分布式、以及团队的运维能力。

Embedding 模型负责把文字变成向量，中文场景常用 BGE 系列（智源开源）和 text-embedding 系列闭源接口，关键指标是语义相似度排序的准确率。生成模型（LLM）的选择要看任务复杂度、成本和延迟：简单问答用轻量模型即可，复杂推理再上大模型。注意 Embedding 模型和生成模型是两个独立的模型，各司其职——前者负责"找"，后者负责"答"。
